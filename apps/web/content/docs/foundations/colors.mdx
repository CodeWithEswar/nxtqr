NXTQR implements a unified **Pure Black Monochrome** color system. The application operates with zero theme switchers, zero light/dark toggles, and zero user-selectable accent colors. Visual hierarchy and interaction feedback are communicated strictly through calibrated neutral grayscale values and solid neumorphic depth.

## Color Architecture & Principles

Per NXTQR Constitution §3, color application follows strict engineering standards:

1. **Pure Monochrome Baseline**: Dark theme surfaces are neutral grayscale with zero blue, slate, or purple tints. Canvas background is permanently pure black (`#000000`).
2. **Prohibited Decorative Accents**: Red buttons, blue active links, violet highlights, and multicolor presets are strictly eliminated. Primary interaction emphasis uses pure white (`#FFFFFF`) or high-contrast neutral gray.
3. **WCAG AAA Compliance Guaranteed**: Primary foreground text against the canvas background achieves a maximum **21:1** contrast ratio.
4. **Solid Opaque Materials**: Surfaces are completely opaque to preserve solid neumorphic physical depth. Translucent blurs and glassmorphism are prohibited.

| Token Name | Hex Value | CSS Variable | Architectural Role | Contrast vs #000 |
| :--- | :--- | :--- | :--- | :--- |
| **Background** | `#000000` | `--background` | Full-page backdrop and infinite visualizer canvas | 1.0:1 |
| **Surface 01** | `#080808` | `--surface-01` | Subtle raised surfaces, bottom toolbars, rail containers | 1.06:1 |
| **Surface 02** | `#0D0D0D` | `--surface-02` | Primary cards, panels, tab stages, inspector bodies | 1.13:1 |
| **Surface 03** | `#141414` | `--surface-03` | Modals, dialogs, floating inspectors, popovers | 1.23:1 |
| **Surface 04** | `#1A1A1A` | `--surface-04` | Active tabs, pressed states, hover feedback | 1.34:1 |
| **Border Subtle** | `#202020` | `--border-subtle` | Fine structural separation, table grid lines | 1.47:1 |
| **Border Default**| `#292929` | `--border` | Standard card boundaries, input frames, component borders | 1.65:1 |
| **Border Strong** | `#404040` | `--border-strong` | Emphasized boundaries, active focus rings, selection frames | 2.16:1 |

## Semantic Status Exceptions

Where functional status information genuinely requires differentiation (e.g., test runner pass/fail or simulation execution state), semantic status tokens are used with accompanying icons and text labels:

- **Destructive / Error**: `#FF0000` (`--destructive`)
- **Success / Passed**: `#00CC66` (`--success`)
- **Warning / Alert**: `#FFD600` (`--warning`)

Status colors must never be used as general UI decoration or button themes.

## Implementation Reference

To apply monochrome tokens in your component markup:

```tsx
import { monochromeTokens } from "@nxtqr/design-system";

// Standard shadcn/Tailwind classes
<div className="bg-black text-foreground border border-border rounded-md">
  <button className="bg-white text-black font-semibold rounded-md shadow-level-1">
    Execute
  </button>
</div>
```
