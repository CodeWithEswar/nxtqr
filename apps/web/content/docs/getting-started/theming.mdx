NXTQR departs fundamentally from generic dashboard aesthetics. Instead of lock-in brand colors, dark blue gradients, or glassmorphic blurs, NXTQR implements a **Pure Monochrome Foundation with User-Selected Pure Accents** and **Restrained Solid Neumorphism**.

> [!IMPORTANT]
> **Constitutional Theming Rules (AGENTS.md)**:
> 1. **Pure Monochrome Base**: The default background is pure black (`#000000`). Foreground text is pure white (`#FFFFFF`). Surfaces follow a strict grayscale hierarchy. Never introduce dark blue, purple, or gradient AI dashboard backgrounds.
> 2. **Never Hardcode Accent Colors**: Components must strictly consume semantic CSS classes (`bg-accent`, `text-accent`, `text-accent-foreground`, `border-accent`, `ring-accent`).
> 3. **WCAG AA/AAA Guaranteed**: Foreground text on accent surfaces is automatically computed via relative luminance mathematics in `@nxtqr/design-system`.
> 4. **Solid Neumorphism**: Depth is achieved via solid layers, directional borders, and restrained shadows. No backdrop blur, glassmorphism, or transparent floating cards.

## Pure Monochrome Surface Hierarchy

NXTQR establishes depth through a calibrated, neutral grayscale token hierarchy rather than colorful backgrounds or translucent overlays:

| Token Name | Hex Value | CSS Variable | Architectural Role |
| :--- | :--- | :--- | :--- |
| **Canvas / Base** | `#000000` | `--background` | Main canvas viewport, full-page background, infinite grid base. |
| **Surface** | `#0A0A0A` | `--surface` | Primary cards, panels, sidebars, and tab containers. |
| **Elevated Surface** | `#141414` | `--elevated-surface` | Floating node inspectors, modal dialogs, popovers, dropdown menus. |
| **Secondary Surface**| `#1A1A1A` | `--secondary-surface`| Inset wells, code blocks, active list rows, pressed controls. |
| **Border** | `#262626` | `--border` | Structural container borders, panel dividers, card boundaries. |
| **Subtle Border** | `#1C1C1C` | `--subtle-border` | Internal table lines, subtle dividers, minor separators. |
| **Foreground Text** | `#FFFFFF` | `--foreground` | Primary titles, body text, active indicators. |
| **Muted Text** | `#A3A3A3` | `--muted-foreground` | Labels, descriptions, secondary metadata, timestamps. |
| **Disabled Text** | `#737373` | `--disabled` | Inactive controls, disabled buttons, placeholder text. |

## Dynamic Contrast Mathematics

The `@nxtqr/design-system` package derives accessible foreground colors dynamically using the standard **W3C WCAG 2.1 Relative Luminance** formula:

```text
L = 0.2126 * R_lin + 0.7152 * G_lin + 0.0722 * B_lin
```

Where linearized channel values are computed as:
- If `C_srgb <= 0.04045`: `C_lin = C_srgb / 12.92`
- If `C_srgb > 0.04045`: `C_lin = ((C_srgb + 0.055) / 1.055) ^ 2.4`

The contrast ratio against white (`L_white = 1.0`) and black (`L_black = 0.0`) is calculated as:

```text
Contrast Ratio = (L_1 + 0.05) / (L_2 + 0.05)
```

If the contrast against black exceeds the contrast against white, `@nxtqr/design-system` automatically assigns `#000000` as the foreground text; otherwise it assigns `#FFFFFF`.

## Solid Neumorphism vs Prohibited Blurs

NXTQR adopts **Solid Neumorphism**—an engineering aesthetic that communicates tactile hierarchy through directional light, sharp edges, and solid opaque surfaces:

- **Level 0 — Base (`#000000`)**: Canvas root and document background.
- **Level 1 — Raised**: Solid `#0A0A0A` surface with `--border` (`#262626`) and subtle directional shadow (`--shadow-level-1`).
- **Level 2 — Elevated**: Solid `#141414` surface with strong elevation (`--shadow-level-2`) for popovers, dialogs, and inspectors.
- **Level 3 — Pressed**: Inset treatment (`--shadow-level-3`) indicating selected toolbar items, pressed buttons, or active node states.

> [!CAUTION]
> **Prohibited Visual Patterns**:
> - **No glassmorphism**: Never use `backdrop-blur-md` or translucent alpha backgrounds on floating UI cards.
> - **No gradients**: Never apply multi-stop linear or radial gradients to body cards or backgrounds.
> - **No arbitrary rounded corners**: Rectangular controls and cards must always use `rounded-md` (`6px`).

## Implementation & Usage

### 1. In React Components

Always reference semantic Tailwind classes for accents:

```tsx
// Correct usage: Consumes semantic CSS variables
export function StatusIndicator({ active }: { active: boolean }) {
  return (
    <div className="flex items-center gap-2 p-2 rounded-md bg-surface border border-border">
      <span className="text-xs text-foreground font-sans">Pipeline Status</span>
      <span className={cn(
        "px-2 py-0.5 rounded text-[10px] font-mono font-bold",
        active ? "bg-accent text-accent-foreground" : "bg-secondary-surface text-muted-foreground"
      )}>
        {active ? "RUNNING" : "IDLE"}
      </span>
    </div>
  );
}
```

### 2. Consuming the Design System Programmatically

Use the `@nxtqr/design-system` utility functions to compute contrast or derive accent shades:

```typescript
import { getAccessibleForeground, deriveAccentShades } from "@nxtqr/design-system";

// Compute accessible foreground with zero page reload
const shades = deriveAccentShades("#00CC66", true);
console.log(shades.foreground); // "#000000"
console.log(shades.muted);      // "rgba(0, 204, 102, 0.12)"
```

### 3. Programmatic State Management

To update the user's accent preference across the studio:

```typescript
import { useThemeStore } from "@nxtqr/state";

// In your settings component or command palette
const setAccentPreset = useThemeStore((s) => s.setAccentPreset);

// Switch to Pure Green
setAccentPreset("green");
```
